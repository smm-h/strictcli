## 0.36.0

Adds the `dryRunSupported: false` command declaration -- a mutating command can now refuse `--dry-run` with a mandatory reason carried into help and the schema -- generates the exported `VERSION` constant from package.json so it can no longer report a version the package never shipped, and rewrites an npm README usage example that did not compile.

<details>
<summary>Context</summary>

`--dry-run` is a promise: the preview must describe what the real run would do.
Some mutating commands cannot keep that promise, because their effects are not
representable ahead of time. Until now such a command either rendered a preview
that misrepresented it or hand-rolled a refusal inside the handler -- after
parsing, invisible to `--help` and to `--dump-schema`. `dryRunSupported` moves the
refusal to the registration site on both twin factories and both passthrough
twins, where the framework can enforce it: the reason is mandatory, it is rendered
in a dedicated `Dry run:` help section, it is emitted in the schema, and declaring
it on a `read_only` command throws at registration (a command that changes nothing
has nothing to preview).

`VERSION` was a hand-written literal with a test pinning that literal, so the test
protected the drift instead of catching it. It is now generated from package.json
by the prebuild hook that `prepack` inherits, and the test asserts agreement with
the manifest rather than a constant.

The same release completes a documentation truth pass. Every registration example
was re-checked against the shipped API, and the reserved flag quartet, the effects
regime and the `consequential` confirm protocol are now documented. Examples are
no longer trusted by inspection: the self-contained example programs are marked
`validate`, and `selfdoc check` now type-checks and RUNS each one against the
built `dist`, so documentation that stops working fails the release.

</details>

### Features

- [ts-strictcli] **`dryRunSupported: false` command declaration.** A mutating command whose effects a preview cannot honestly represent can now declare `dryRunSupported: false` with a mandatory `dryRunUnsupportedReason` on the twin factories and the passthrough twins. `--dry-run` is then refused at parse time with the reason instead of rendering a preview that would misrepresent the real run; the reason also appears in a new `Dry run:` help section and in the schema. Declaring it on a `read_only` command throws at registration time.

### Fixes

- [ts-strictcli] **`VERSION` no longer lies.** The exported `VERSION` constant is now generated from `package.json` at build time, so it always matches the published package version -- it previously reported `0.31.0` in packages published as 0.35.0.
- [ts-strictcli] **The npm README's usage example now compiles.** It imported and called a `command()` factory that was removed when classification became mandatory, passed flags as an array instead of a keyed map, used a nonexistent `required: true` flag option, called `createApp` with a positional name and a `commands` key that `AppSpec` has never had, and declared a flag named `dry-run` -- a framework-reserved name that throws at registration. The example is now a working `createApp` + `defineMutatingCommand` program, and the feature list documents the twin factories, the effects regime, `dryRunSupported` and the confirm protocol.
