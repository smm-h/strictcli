## 0.33.0

The declaration-regime release: mandatory presence declarations, scoped selectors replacing mutex groups, real-JSON-Schema value fragments (schema v2), the co-occurrence constraint system, and the update-command construct.

<details>
<summary>Context</summary>

The declaration-regime campaign closes the last places where strictcli inferred something the developer had not written down: presence is now declared on every flag and arg, exactly-one selection is a scoped choice flag rather than a mutex group, `--dump-schema` publishes real JSON Schema value fragments at schema version 2, co-occurrence rules are one named constraint container, and an update command declares the resource, write mode, identity and properties it writes. Consumers must migrate their declarations before adopting this version: the new rules are registration-time hard errors, so an unmigrated app fails to build rather than misbehaving, and a repo that has not migrated simply stays on the previous floor until it does.

</details>

### Breaking

- [go-strictcli] **Presence is now declared, never derived.** Every flag declares exactly one of `Required()`, `Optional()` or `Default(v)`, and every positional arg one of `ArgRequired()`, `ArgOptional()` or `ArgDefault(v)`. Declaring none or two is a registration-time hard error, `Default(nil)` is refused with a redirect to `Optional()`, and `ArgRequired(bool)` is gone. Optional flags deliver nil (bools become real tri-state), compound flags no longer get a silent empty default, a mutex member declares its own absence, a `Flag` struct literal no longer registers, the dumped schema carries `presence` on every flag and arg entry, MCP tool schemas take requiredness from the declaration (required bools now appear), help renders exactly one presence part per line, and `ctx.Provided(name)` reports whether the invocation caused a value.
- [go-strictcli] **`MutexGroup` is removed.** Exactly-one-of-these is a member-spelled choice flag now, which carries the same rule with the type information kept rather than thrown away, gives each member a scope of its own, and reproduces the mutex error sentences byte-for-byte. There is no shim and no deprecation period: replace `WithMutex(MutexGroup{Flags: []Flag{...}})` with `WithFlags(MemberChoiceFlag(name, help, Required(), MemberChoice(...), ...))`. A member flag now declares `Required()` (read as *required once this member is elected*), inverting the old rule that forbade it, and the handler receives one tagged record instead of one value per member.
- [go-strictcli] **A choices entry is always a record.** `Choices(...)` and `ArgChoices(...)` take `Ch(<value>, "<help>")` entries; the bare-value spelling is deleted, so `Choices("head", "tags")` becomes `Choices(Ch("head", "push only the current HEAD branch"), Ch("tags", ""))`. Help on an entry is optional -- `""` is the no-help spelling -- and a flag whose entries carry help renders as an indented block instead of the one-line `[choices: a, b]` form.
- [go-strictcli] **`FlagOption` is an interface.** `type FlagOption interface{ applyFlag(*Flag) }` replaces the `func(*Flag)` type, which is what lets a choice be a value with identity that a handler switches on by reference. Every constructor keeps its signature -- `Required()` still returns `FlagOption` and still compiles at every call site. The one caller shape that breaks is a hand-written `strictcli.FlagOption` func literal, which could only ever reach `Flag`s exported fields, could not declare presence, and therefore already failed registration.
- [go-strictcli] **Sibling scopes reusing a short are now checked.** §24.7 lets two scopes that can never be live together claim one short, and two declarations that were silently accepted are refused at registration: `command "run": short '-t' is claimed by '--target' and '--tag' with different value shapes` when the reuse would make tokenization depend on the election, and `short '-t' is reused by sibling scopes and also claimed by '--transport', which elects` when one claimant is itself an election token. The claim table walks member scopes too, so two member flags sharing a short are refused by the second rule.
- [go-strictcli] **`--dump-schema` writes schema version 2.** A flag or arg entry carries a real JSON Schema fragment under `value_schema`, from a closed subset of `type`, `items`, `additionalProperties` and `enum` with JSON Schema's own type names; the `type` key (`"list[str]"`, `"dict[str]"`) and the `repeatable` key are gone, because arity is a property of the value and a repeatable flag publishes the same array fragment a list-typed flag does. A value flag's `Choices(...)` splits in two: the values as an `enum` inside the fragment, and the value-plus-help records beside it under `choices` (`help` omitted when an entry declares none) -- and an integer choice beyond ±2^53 is refused at registration, because a reader that parses JSON numbers as IEEE-754 doubles reads a different integer back (declare a big identifier as a string; float choices are unaffected). A choice flag has no fragment at all -- its value is a variant the subset cannot express -- and instead publishes its nested choices and scopes, each scoped entry a full flag entry, with `elect_by` as the discriminator. Every entity's keys are emitted in a declared order rather than Go's map-marshal sort, and the document is written by a canonical writer (canonical floats, raw UTF-8, no HTML escaping, two-space indent, one trailing newline) so two implementations' dumps are byte-comparable. The `defaults` block is rewritten as the complete map of what an omitted key means, and the dump stops being blind to behavior: `config_format`, `config_path`, `config_conflict_mode`, per-flag `prefixed` and per-command `flag_sets` each appear exactly when a declaration departs from the framework's own behavior, `config_path` publishes the declaration rather than the machine's resolution of it, and the `checks` block is a function of the declaration alone rather than of whether a check has run in this process.
- [go-strictcli] **A choice name must match `[a-z][a-z0-9-]*`, checked at registration.** A choice name is a surface name whatever elects it: a token-spelled choice flag publishes it in an enum, and under member spelling it is the flag that elects the choice. `Choice("Email", ...)` and `MemberChoice(BoolFlag("all_profiles", ...), ...)` are now refused with `Flag "via": choice name "Email" must match [a-z][a-z0-9-]*`, in both spellings, where they registered before.
- [go-strictcli] **`Elected.Provided` over a caller-supplied record now answers `false` for every field.** The record door labels every field it delivers as the declaration's, so a handler can no longer tell a field an `app.Call()` record supplied from one the declaration filled in -- a member's payload and a nested selection included. A `RelativeToRoot` default resolved at that door still reports `infra`. The command line and the flat door are unaffected and still answer what the invocation caused.
- [go-strictcli] **Constraints, reshaped.** `CoRequired` is deleted and `AllOrNone` takes its place beside a new `AtLeastOne`, both declared through `WithConstraints(...)` with a mandatory name. A member is a flag, a positional arg or another named constraint, nested to unlimited depth, and declares when it engages with `WhenPresent()` / `WhenTrue()` / `WhenNonEmpty()` -- a bool member must declare it, so `--no-x` can no longer engage a constraint while selecting nothing. `Requires` and `Implies` keep their semantics and become constructors taking the same mandatory name. No member may declare `Required()`. Constraints now render in `--help`, publish members in `--dump-schema`, and project into MCP tool schemas.
- [go-strictcli] **Three breaking changes, all of them the update-command round's.** (1) The mutating-default ban: a flag or positional arg on a command declaring `effect="mutating"` may no longer declare a value default, because on a mutating command a value the framework picked is a value the framework writes -- empty collection defaults, `RelativeToRoot` defaults, a choice flag's own default and every declaration on a read_only command stay legal. (2) `config set` takes its value under `--value`: its write is now an exactly-one selection over a value, a clear and a reset to default (`config set <key> --value <v>`), and supplying none or two of the three is refused by the framework rather than by the command. (3) The machine envelope gains a `writes` member carrying an update command's write set, and `interface_version` becomes `2`.

### Features

- [go-strictcli] **README explains the Go-shaped declaration surface.** The package README now states that the Go implementation is not a port of the Python or TypeScript ones: the surface is Go's own (functional options, typed constants, generics, a panic at registration), the presence options write an unexported field so a bypassing `Flag` struct literal fails to register instead of silently dropping its value, and what the three implementations hold identical is behavior rather than spelling.
- [go-strictcli] **Choice flags: a choice is a declaration scope.** `ChoiceFlag(name, help, ...)` elects exactly one of its declared `Choice(name, help, flags...)` values, and each choice owns the flags that exist only while it is elected. `MemberChoiceFlag` with `MemberChoice(memberFlag, help, scope...)` is the member-spelled twin, where each choice is its own flag and no selector token is ever typed. The elected value reaches the handler as one `*Elected` carrying `Fields`, consumed by `GetElected` plus `Match`/`When` -- which are compile-checked references to the choice values themselves and exhaustive against the declaration at dispatch. Parsing stays order-independent, choice flags nest to any depth, and a flag supplied outside its elected scope is a distinct parse error naming the flag, its owning choice and the choice that was elected -- never "unknown flag".
- [go-strictcli] **A positional arg with helped choices renders an indented block.** The block rule was always content-keyed -- any `ArgChoices(Ch(value, help))` entry carrying help -- and it now reaches positional args exactly as it reaches flags: the entries render beneath the arg's line with their help, the one-line `[choices: a, b]` part is dropped in that form, and one alignment column is computed across the whole `Arguments:` section, deepest entry included.
- [go-strictcli] **A list-typed variadic arg may declare choices.** `NewArg("envs", help, ArgType(ListOf(TypeStr)), Variadic(), ArgChoices(...))` was refused with `choices is incompatible with list type` while the same arg declared with the scalar element type was accepted. The two spellings are one declaration with one published shape, so the ban is deleted and the entries are checked against the element type in both.
- [go-strictcli] **The README documents the choice flag and the choices record.** The mutually-exclusive-flag-groups section is replaced by a choice-flag section covering `Choice`/`ChoiceFlag`, `MemberChoice`/`MemberChoiceFlag`, identity-checked `Match`/`When` over `*Elected`, and the presence rules; the choices section shows the `Ch(<value>, "<help>")` record spelling that replaced bare values; and the constructor list, flag-option table and core-type table follow.
- [go-strictcli] **A list carrier may declare choices.** `ListFlag(TypeStr, "tags", help, Unique(false), Choices(Ch("a", ...), Ch("b", ...)))` was refused at registration with `choices is incompatible with compound types (list/dict)` although the dumped `value_schema` and the MCP tool schema already published the enum inside `items`. Choices on a list carrier constrain each ELEMENT, and are checked per element on the command line, from an env var and on a declared default alike. The ban survives for a dict -- whose keys are structurally strings and whose values are not a closed set -- and now reads `Flag "header": dict type cannot be combined with choices`, the siblings' own sentence.
- [go-strictcli] **The update-command construct.** `WithUpdateOf(resource, WriteSparse|WriteFullReplace, Identity(...), Properties(first, rest...))` declares what a command updates: which flags and args name the instance, which flags carry what changes, and whether the write is sparse or a full replace. The framework enforces that at least one property is supplied, renders the write set on every surface a run reports through -- one unnumbered line in the would-do log and a `writes` member on the machine envelope -- and publishes the declaration in `--dump-schema` and in the MCP tool schema. A property declares `Optional()`: absence means untouched.
- [go-strictcli] **The package README documents the update-command construct.** An Update commands section covers `WithUpdateOf` with the write mode as a positional parameter, `Properties`' compile-time floor of one, the at-least-one-property refusal, the mutating-default ban, `Nullable()` and the write set's two renderings; the config section carries `config set`'s reshaped `--value` argv.

### Fixes

- [go-strictcli] **A custom validator runs on a supplied value only.** `ValidateFn` no longer runs against a declared `Default(v)` -- including a `RelativeToRoot` default, whose `infra` source is still the declaration deciding. It runs when the invocation caused the value (`cli`, `env`, `config`, `implied`), which is the same definition `AllOrNone`, `Requires` and `ctx.Provided` use.
- [go-strictcli] **Help output fixes.** A `RelativeToRoot` default now renders as its declaration (`[default: RelativeToRoot('MYAPP_ROOT', 'store')]`) instead of Go's internal struct form, and `--help`/`-h` after a command group's name shows the group's help whatever follows it (`myapp db --help ./path` no longer reports an unknown command).
- [go-strictcli] **Choice-flag help lines are corrected.** A member-spelled selector renders its own name in the left column and `(exactly one of the following)` after its help text in the right one, with its member flags two columns beneath it rather than four; a payload-less member renders `--all-profiles` rather than `--all-profiles, --no-all-profiles`, because the negation declines rather than electing; and a defaulted selector renders the complete elected value, `[default: webhook (url=https://example.test/hook, retries=5)]`, instead of the choice name alone -- a choice whose scope is empty still renders `[default: <choice>]`, and a nested selector states its own default on its own line.
- [go-strictcli] **A bare `ArgChoices` entry reports the arg, not a flag that does not exist.** `ArgChoices(strictcli.ChoiceValue{Value: "head"})` panicked with `Flag "target": choices entry 0 is a bare value`; it now reads `Arg "target": ...`, because both surfaces went through one validator that took the flag prefix as a constant.
- [go-strictcli] **A structural parse problem is now reported ahead of a value that will not parse.** An unknown flag, an unknown choice and a scope violation are facts about the command line's shape, and shape is decided before any token's text is interpreted -- on every command, not only on one that declares a choice flag. `myapp cmd --count abc --unknown` reported `--count: expected integer, got 'abc'` and now reports `unknown flag '--unknown'`, and the answer no longer depends on which token came first.
- [go-strictcli] **The MCP tool schema describes array parameters correctly.** A parameter whose value is a list carried its `enum` at the property root, which said the array itself had to equal one of the choices; it now sits inside `items`, describing an element. The projection derives every parameter's shape from the same fragment the dumped `value_schema` publishes, so a tool schema and a dumped schema cannot disagree about a value's shape.
- [go-strictcli] **A payload-less member publishes no MCP property.** The electing member flag was projected as an ordinary scoped flag, so a member carrying no payload contributed a spurious boolean property beside the selector's own enum -- a second spelling of an election the enum already carries, and one no caller could usefully send. A payload-carrying member now contributes exactly its payload property, under its own name and with its own value schema, and a payload-less one contributes nothing at all.
- [go-strictcli] **A member's payload key elects that member at the machine boundary.** The flat form `App.Call` and MCP take has no tokens, so supplying the property that flattens under a member's own flag name IS that election: `{"profile": "work"}` now elects `--profile` and carries its value, exactly as `--profile work` does on the command line. Supplying one member's payload beside a selector key naming a DIFFERENT member is a double election, and where it was previously accepted with the payload silently dropped it is now refused with the CLI's own sentence -- `--profile and --all-profiles are mutually exclusive` -- over MCP as an ordinary tool-result error.
- [go-strictcli] **A member name colliding with a command-level flag is reported as the duplicate flag name it is, and an out-of-scope member flag names the scope that owns it.** Under member spelling a choice name IS a flag name: `MemberChoice(StringFlag("profile", ...), ...)` declared beside a command flag named `profile` now panics `command "run": duplicate flag name "profile"` instead of the unreachable-scoped-flag message. And a member flag supplied outside its scope reported `flag '--profile' is only valid under '--mode advanced --profile'`, appending the member's own election to the path it is missing from; it now stops at the scope that owns it, `'--mode advanced'`, while a flag declared INSIDE a member's scope keeps every segment.
- [go-strictcli] **Electing a member without its payload is refused with the command line's own sentence.** At the flat machine boundary `App.Call` and MCP take, naming a payload-carrying member under the selector's own key without supplying that member's value -- `{"target": "profile"}` -- reported `flag '--profile' is required under '--profile'`, naming the flag as its own owner. It is now `flag '--profile' requires a value`, the bytes the same mistake gets when typed on the command line. A record handed to `App.Call` whose `Fields` omit "value" takes the same refusal.
- [go-strictcli] **Every selector's election is resolved before any value is refused at the flat machine boundary.** A wrong value in one selector's elected scope -- or on one of the command's own flags -- outranked a later selector's double election, so `{"via": "email", "header": "not-a-map", "target": "all-profiles", "profile": "work"}` reported the dict type refusal where the same command line reports `--profile and --all-profiles are mutually exclusive`. Elections now stage command-wide first, exactly as they do on the command line, and the value sweep that follows runs in declaration order rather than Go's map iteration order.
- [go-strictcli] **The machine boundary and `App.Call` answer with the command line's own sentences, in the command line's own order.** Three refusals were wrong. A pre-typed value was taken as given, so `"retries": "3"` reached an `IntFlag` as a string, `"profile": 42` reached a `str`-declared member payload as an int, and an explicit `nil` satisfied a required declaration; every supplied value is now checked against the type its declaration names -- at command level, inside a scope, on a member's payload and on an app-level global alike -- with the sentences the config reader already uses (`--retries: expected integer, got str`), and `nil` is a legal value for nothing: a flag that may be absent declares `Optional()` and is delivered absent when the key is omitted. A key spelled with dashes named nothing and was treated as if it did: `"keep-going": "yes"` was accepted and delivered at root, and `"phone-number": "555"` was half-read inside a scope -- counted for scope validation while its value was never read, so under its own elected scope the flag it named was reported missing. Each is now `unknown parameter "phone-number" for command "run"`, refused ahead of every election, scope, value and presence problem, as is a key naming nothing beside a selector property naming no declared choice. And a positional's value was stringified through `%v` rather than checked, so `7` satisfied a `str`-declared arg and a `nil` arrived as the text `<nil>`; a positional now takes its declaration's own check (`argument 'count': expected integer, got str`), is delivered as supplied, and binds to the arg its key names rather than to whatever position the supplied subset left it in.
- [go-strictcli] **A value refusal at the programmatic doors follows the command's own declaration order.** The value stage swept every elected scope first and the command's own flags second, so a flag declared *before* a selector reported its wrong-typed value after anything inside that selector's scope -- `{"count": "nope", "via": "email", "retries": "nope"}` answered `--retries` where the same command line answers `--count` -- and a nested selector's values were read after the whole scope holding them rather than where the nested selector is declared. There is now ONE declaration-ordered sweep at every depth: each declaration in the order it was written, a selector taking its position in that walk, and its elected record's values read at that position, with the app's globals after all of them.
- [go-strictcli] **A key an elected record's scope does not declare is refused.** `Elect(email, Fields{"retries": 1, "bogus": 2})` ran the handler with the extra key dropped in silence: the record was read by walking the scope's declarations, so a key no declaration names was never looked at. A record's key namespace is the elected choice's own scope -- its payload key and the parameters that scope declares at that level -- and anything else is now `unknown parameter "bogus" for command "run" under '--via email'`, at every depth, carrying the full scope path. It is a fact about the object's shape, so it is reported ahead of every election, scope, value and presence problem the same call contains. A parameter a sibling scope declares is an unknown key inside a record too; supplied at the flat form's top level it keeps the out-of-scope sentence it already had.
- [go-strictcli] **An explicit `nil` on an optional scoped field at the record door now delivers absence.** `app.Call("send", map[string]interface{}{"via": Elect(email, Fields{"subject": nil})})` is a record's only way to spell an unset optional field -- a scope has no key to omit -- and it is now delivered as a present field holding nothing instead of being refused with `--subject: expected string, got null`. Required fields, defaulted fields and every value at the flat door are unchanged.
- [go-strictcli] **A field of a record handed to `app.Call()` is checked against its declared TYPE and nothing else.** That door also ran the `Choices` closed-set check and the custom `ValidateFn` over every field a record supplied, so a scoped value outside its `Choices` list was refused here and delivered by the sibling implementations. Both halves are now deferred at the record door; the command line and the flat door keep them unchanged.
- [go-strictcli] **`config show --json` publishes a `RelativeToRoot` default as the marker shape the document pins.** A flag defaulted to a marker appeared in the machine payload as `"value": {}` -- an empty object, because the marker's fields are unexported -- where the schema dump has always published `{"relative_to_root": {"env_var": ..., "parts": [...]}}` for the same declaration. Both surfaces now agree. The human form is unchanged: it still prints the declaration as written, labelled `default`.
