## 0.41.0

The declaration-regime release: mandatory presence declarations, scoped selectors replacing mutex groups, real-JSON-Schema value fragments (schema v2), the co-occurrence constraint system, and the update-command construct.

<details>
<summary>Context</summary>

The declaration-regime campaign closes the last places where strictcli inferred something the developer had not written down: presence is now declared on every flag and arg, exactly-one selection is a scoped choice flag rather than a mutex group, `--dump-schema` publishes real JSON Schema value fragments at schema version 2, co-occurrence rules are one named constraint container, and an update command declares the resource, write mode, identity and properties it writes. Consumers must migrate their declarations before adopting this version: the new rules are registration-time hard errors, so an unmigrated app fails to build rather than misbehaving, and a repo that has not migrated simply stays on the previous floor until it does.

</details>

### Breaking

- [strictcli] **Presence is now declared, never inferred.** Every flag and every positional argument must declare exactly one of `presence="required"`, `presence="optional"` or `default=<value>`; declaring none or two is a registration-time error. `default=None` is refused with a redirect to `presence="optional"`, the arg `required=` field is deleted, a repeatable or dict flag no longer defaults silently to `[]` / `{}`, and a mutex member declares its own optionality instead of receiving an exemption.
- [strictcli] **`MutexGroup` is removed.** Exactly-one-of-these is now a member-spelled choice flag, which carries the same rule with the type information kept rather than thrown away, adds a scope per member, and reproduces the mutex error sentences byte-for-byte. There is no shim and no deprecation period: replace `mutex=[MutexGroup(flags=[...])]` with `@strictcli.choice_flag(..., elect_by="member-flags", choices=[...])`, one `@strictcli.choice` class per member. A member flag now declares requiredness (read as *required once this member is elected*), inverting the old rule that forbade it.
- [strictcli] **A `choices=` entry is always a record.** The bare-value entry is deleted: write `choices=[strictcli.Choice("head", help="push only the current HEAD branch"), strictcli.Choice("tags")]` instead of `choices=["head", "tags"]`, on flags and on positional args alike. Help on an entry is optional, and a flag whose entries carry help renders as an indented block instead of the one-line `[choices: a, b]` form. A bare entry is refused at registration with the record spelling in the message.
- [strictcli] **An integer `choices=` entry beyond ±2^53 is refused at registration.** The dumped schema publishes a declaration's choices as a JSON Schema `enum`, and a reader that parses JSON numbers as IEEE-754 doubles -- which every reader of a schema file is entitled to be -- reads a different integer back. Declare a big identifier as a string instead. Float choices are unaffected: the canonical float form round-trips exactly, so nothing is lost there.
- [strictcli] **`--dump-schema` writes schema version 2.** A flag or arg entry carries a real JSON Schema fragment under `value_schema`, from a closed subset of `type`, `items`, `additionalProperties` and `enum` with JSON Schema's own type names; the `type` key and the `repeatable` key are gone, because arity is a property of the value and a repeatable flag publishes the same array fragment a `list[T]` flag does. A value flag's `choices=` splits in two: the values as an `enum` inside the fragment, and the value-plus-help records beside it under `choices` (`help` omitted when an entry declares none). A choice flag has no fragment at all -- its value is a variant the subset cannot express -- and instead publishes its nested choices and scopes, each scoped entry a full flag entry, with `elect_by` as the discriminator; choice flags now sit in the command's one `flags` array in declaration order rather than a separate key. Every entity's keys are emitted in a declared order, the document is written in one canonical encoding (canonical floats, raw UTF-8, no HTML escaping, two-space indent, one trailing newline) so two implementations' dumps are byte-comparable, and the `defaults` block is rewritten as the complete map of what an omitted key means. The dump also stops being blind to behavior: `config_format`, `config_path`, `config_conflict_mode`, per-flag `prefixed` and per-command `flag_sets` each appear exactly when a declaration departs from the framework's own behavior, `config_path` publishes the declaration rather than the machine's resolution of it, and the `checks` block is a function of the declaration alone rather than of whether a check has run in this process.
- [strictcli] **Constraints, reshaped.** `CoRequired` is deleted and `AllOrNone` takes its place beside a new `AtLeastOne`, both declared through `constraints=[...]` with a mandatory name. A member is a `Member(name, when=...)` record naming a flag, a positional arg or another named constraint, nested to unlimited depth, and a bare string is refused; `when` is `"present"` / `"true"` / `"non_empty"`, and a bool member must declare it, so `--no-x` can no longer engage a constraint while selecting nothing. `Requires` and `Implies` keep their semantics and take the same mandatory name. No member may declare `presence="required"`. Constraints now render in `--help`, publish their members in `--dump-schema`, and project into MCP tool schemas.
- [strictcli] **Three breaking changes, all of them the update-command round's.** (1) The mutating-default ban: a flag or positional arg on a command declaring `effect="mutating"` may no longer declare a value default, because on a mutating command a value the framework picked is a value the framework writes -- empty collection defaults, `RelativeToRoot` defaults, a choice flag's own default and every declaration on a read_only command stay legal, and a defaulted selection's instance may pass no field values. (2) `config set` takes its value under `--value`: its write is now an exactly-one selection over a value, a clear and a reset to default (`config set <key> --value <v>`), and supplying none or two of the three is refused by the framework rather than by the command. (3) The machine envelope gains a `writes` member carrying an update command's write set, and `interface_version` becomes `2`.

### Features

- [strictcli] **`ctx.provided(name)`, and presence published everywhere it is asked about.** `ctx.provided` answers whether the invocation caused a flag's value -- true for `cli`, `env`, `config` and `implied`, false for `default` and `infra` -- so no handler reconstructs that boolean out of `ctx.source`. `--dump-schema` emits a `presence` key on every flag and arg entry, plus a `default` exactly when presence is `"default"` (empty collections included); help renders exactly one marker per line (`[required]`, `[optional]` or `[default: <value>]`), with required positionals and declared empty collections now visible; and MCP tool schemas read requiredness straight off the declaration.
- [strictcli] **README explains the Python-shaped declaration surface.** The package README now states that the Python implementation is not a port of the Go or TypeScript ones: the surface is Python's own (decorators, keyword arguments, the `Flag` dataclass, `ValueError` at registration), some enforcement exists only in Python, and what the three implementations hold identical is behavior rather than spelling.
- [strictcli] **Choice flags: a choice is a declaration scope.** A choice flag elects exactly one of its declared choices, and each choice owns the flags that exist only while it is elected. `@strictcli.choice` declares a choice as a frozen dataclass whose fields (declared with `strictcli.sub_flag` / `sub_choice_flag`) are the scope's flags; `@strictcli.choice_flag` attaches the selector, with `elect_by="selector-token"` (`--via email`) or `elect_by="member-flags"` (`--profile work` / `--all-profiles`, payload declared with `strictcli.member_value`). The elected value reaches the handler as one tagged record consumed by `match`, parsing stays order-independent, and choice flags nest to any depth. A flag supplied outside its elected scope is a distinct parse error naming the flag, its owning choice and the choice that was elected -- never "unknown flag". `strictcli.provided(record, "subject")` answers provided-ness inside a record; an env var or config key bound to a flag in a non-elected scope is not consulted and is named under `--verbose`; and the MCP projection flattens the scope into top-level properties (never in `required`) while publishing the scope structure in the tool description and refusing wrong combinations at call time with the CLI parser's own sentence.
- [strictcli] **A positional arg with helped choices renders an indented block.** The block rule was always content-keyed -- any `choices=` entry carrying help -- and it now reaches positional args exactly as it reaches flags: the entries render beneath the arg's line with their help, the one-line `[choices: a, b]` part is dropped in that form, and one alignment column is computed across the whole `Arguments:` section, deepest entry included.
- [strictcli] **The README documents the schema-v2 dump and the scoped declaration surface.** The schema-dump section now states `schema_version: 2`, the `value_schema` fragment on every flag and arg entry, the choice flag's fragment-less `choices` plus `elect_by` encoding, and the canonical encoding that makes the three implementations' dumps byte-identical. The API tables gain `sub_flag`, `sub_choice_flag`, `member_value` and `provided`.
- [strictcli] **The update-command construct.** `UpdateOf(resource, write_mode="sparse"|"full_replace", identity=[...], properties=[...])` declares what a command updates: which flags and args name the instance, which flags carry what changes, and whether the write is sparse or a full replace. The framework enforces that at least one property is supplied, renders the write set on every surface a run reports through -- one unnumbered line in the would-do log and a `writes` member on the machine envelope -- and publishes the declaration in `--dump-schema` and in the MCP tool schema. A property declares `presence="optional"`: absence means untouched, and `nullable=True` mints `--unset-<prop>`, answered by `ctx.unset(name)`.
- [strictcli] **The package README documents the update-command construct.** An Update commands section covers the `UpdateOf` record, the property presence rule, the at-least-one-property refusal, the mutating-default ban, the clear vocabulary and the write set's two renderings; the config section carries `config set`'s reshaped `--value` argv.

### Fixes

- [strictcli] **A positional argument's bool default renders lowercase in help.** A positional now shows `[default: true]` / `[default: false]` exactly as a flag does; it rendered `[default: True]` through Python's own `str`, so a single help page could show both spellings of the same value. Every other value type -- strings, numbers, collections -- already rendered identically on both surfaces and is now pinned that way.
- [strictcli] **Fixed positional arg order with stacked `@strictcli.arg` decorators.** Two or more stacked `@strictcli.arg` decorators bound argv bottom-up, so the arguments were assigned in reverse declaration order (and listed reversed in help). They now bind top-down, matching the `args=[...]` list form.
- [strictcli] **A structural parse problem is now reported ahead of a value that will not parse.** An unknown flag, an unknown choice and a scope violation are facts about the command line's shape, and shape is decided before any token's text is interpreted -- on every command, not only on one that declares a choice flag. `myapp cmd --count abc --unknown` reported `--count: expected integer, got 'abc'` and now reports `unknown flag '--unknown'`, and the answer no longer depends on which token came first.
- [strictcli] **The MCP tool schema describes array parameters correctly.** A parameter whose value is a list carried its `enum` at the property root, which said the array itself had to equal one of the choices; it now sits inside `items`, describing an element. Two shapes were also projected as scalars and are now arrays: a repeatable flag and a variadic positional arg. All three follow from one arity rule, which the dumped `value_schema` fragment states as well, so a tool schema and a dumped schema cannot disagree about a value's shape.
- [strictcli] **A member's payload key elects its member at the machine boundary.** In the flat form the MCP and programmatic surfaces take, a payload key belonging to a member the selector key did not name was silently discarded: `{target: "all-profiles", profile: "work"}` ran with `all-profiles` elected and the profile name thrown away. Supplying a member's payload key is now electing that member, so that pair is refused as the double election it is, with the parser's own sentence (`--profile and --all-profiles are mutually exclusive`), and a payload key sent alone elects its member exactly as `--profile work` does on the command line.
- [strictcli] **The flat machine boundary reads a member key as the token it spells.** Two states of the flat form the MCP and programmatic surfaces take were answered wrongly. A key under a payload-less member's own name was ignored entirely, so `{all_profiles: true}` was refused with `one of --profile, --all-profiles is required` where `--all-profiles` elects on the command line; it now elects on `true` and declines on `false` exactly as `--no-all-profiles` does, decline clause included. And naming a payload-carrying member under the selector's own key without supplying that member's value -- `{mode: "profile"}` -- handed the command a record whose `str`-annotated, required field held `None`; it is now refused with the sentence the same mistake gets when typed, `flag '--profile' requires a value`. Both ride the ordinary tool-result error channel over MCP.
- [strictcli] **A scoped flag's `RelativeToRoot` default reaches the handler as a path.** Declared inside a choice's scope, the marker was delivered as the `RelativeToRoot` object itself with source `default`, where the same declaration on a command-level flag delivers the resolved path with source `infra`. It now resolves through the declared infrastructure root at every depth, on the command line and at the machine boundary alike, and a marker naming an undeclared root is refused with the scope it was declared in.
- [strictcli] **An unsatisfied member-spelled selector names the ambient election that caused it.** `one of --profile, --all-profiles is required under '--via email'` left out the clause naming the environment variable that elected the scope the requirement lives in, so the refusal blamed a command line that did not contain the cause. The three clauses now compose in one order -- scope, then origin, then the decline note -- with both parentheticals following a complete sentence.
- [strictcli] **An unknown property is reported first at the machine boundary.** A key naming nothing the command declares reached its check only after the selectors had been converted, so it lost to whatever that work found: `{"mode": "profile", "nope": 1}` reported the missing payload and `{"profile": "work", "all_profiles": true, "nope": 1}` reported the double election. The unknown key is a fact about the object's shape and now outranks every election, scope, value and presence problem, exactly as an unknown flag does on the command line wherever it sits in argv.
- [strictcli] **A value handed to `call()` or to the flat machine form must satisfy its declaration.** Pre-typed meant unchecked: `count="7"` reached an `int` flag as a string, `profile=42` reached a `str` member payload as an int, and an explicit `None` satisfied a required declaration -- at command level, inside a scope and on a member's payload alike. Every supplied value is now checked against the type its declaration names, with the sentences the config reader already uses (`--count: expected integer, got str`), and `None` is not a legal value for anything: a flag that may be absent declares `presence="optional"` and is delivered absent when the key is omitted.
- [strictcli] **A positional handed to `call()` or to the flat machine form must satisfy its declaration.** A positional's value was stringified into a token the caller never wrote: `target=None` reached a `str`-declared arg as the four characters "None", `target=5` reached it as "5", and an `int`-declared arg accepted the numeral's text and re-parsed it. An arg declares the same three presence spellings and the same four types a flag does, so a supplied value is now checked against the type its declaration names -- `argument 'count': expected integer, got str` -- and handed to the handler as supplied. `None` is a legal value for nothing here either: an arg that may be absent declares `presence="optional"` and is delivered absent when the key is omitted. A variadic arg is a sequence of positionals, so an array spreads into one element per entry and each element is checked on its own.
- [strictcli] **A required bool inside a choice's scope names the tokens that satisfy it.** Declared one level down, `watch: bool = sub_flag(presence="required")` was refused with `flag '--watch' is required under '--via email'`, where the same declaration at command level reads `flag '--watch' must be passed as --watch or --no-watch` -- so one declaration said two different things about itself depending on where it was written, and the scoped form dropped the pair of tokens the sentence exists to name. The scoped path now composes the scope suffix, and the origin suffix when an ambient election caused the requirement, onto the sentence the declaration itself takes, and a non-negatable bool names its one token. A value flag keeps `is required`.
- [strictcli] **A value inside an elected record must satisfy the declaration it is supplied against.** `call()` takes the elected record pre-typed, and delivered every field of it unchecked: `via=Email(retries="3")` reached an `int`-declared field as a string, `Email(retries=None)` answered a required field's presence rule with a null, `mode=Profile(value=42)` reached a `str`-declared payload as an int, and a field bound to a nested choice flag was delivered whatever it held, record or not -- while the flat machine form refuses every one of the same values under the same declarations. Every field is now checked against the type its declaration names, at every depth, and a `RelativeToRoot` default carried by a supplied record resolves to its path with source `infra` as it does at every other door. The door also decides the whole command before it reports: a record naming no declared choice is heard over a wrong-typed field beside it, and a wrong-typed field over a selector nobody elected.
- [strictcli] **The programmatic doors read numbers, value order and declared markers as the declaration says.** Three fixes to `call()` and the flat machine form. (1) At the flat machine boundary an integral number now satisfies an `int` declaration -- JSON has one number type and a document may write an integer as `7.0`, which Python's decoder hands over as a float, so `{"retries": 7.0}` was refused here while every other reader accepts it; flags, repeatable elements, dict values and positionals alike, with a fractional number keeping its refusal and `call(retries=7.0)` still refused because `call()` takes Python's own values. (2) A value refusal now follows the command's own declaration order at both doors: they swept every elected scope first and the command's own flags second in the caller's key order, so a flag declared *before* a selector answered after anything inside that selector's scope, and the flat door even decided a scoped flag's *presence* before reading any root value. There is now ONE declaration-ordered sweep at every depth, the app's globals after it, and presence strictly behind every value in the call. That order is the two programmatic doors' own: the command line is not a party to it and reports in the order its tokens were typed. (3) A `RelativeToRoot` field of a defaulted selection now resolves at delivery -- source `infra`, at every door and every depth -- where it used to reach the handler as the marker object itself, and the selection's compound defaults are copied so a handler cannot mutate the declaration.
- [strictcli] **The command line's value phase now reports in the order the tokens were typed.** `myapp run --via email --retries nope --before nope` named the root flag's refusal whatever the order, because root values were resolved ahead of every scoped one; both refusals are true and the one printed is now the token that comes first. Two more consequences of the single sweep: every occurrence of a scoped flag is coerced where it was typed, so `--retries nope --retries 1` reports the token that will not parse instead of quietly keeping the last one, and a scoped `validate` callback can no longer refuse ahead of a later token's coercion failure. `call()` and the flat machine form are unchanged.
- [strictcli] **A `RelativeToRoot` naming an undeclared infra root inside a choice scope now says what elected that scope.** The refusal named where the declaration lives (`... under '--via email'`) and stopped there, even when nothing in the invocation elected that scope -- so a selection the declaration itself made went unnamed on the one message written to name it. It now reads `... under '--via email' (elected by default)`, at the command line, at `call()`'s flat form and at its record form alike. An outer scope elected from an environment variable still names the variable instead, and an election the caller supplied earns no clause at all.
- [strictcli] **`config show --json` no longer fails on a flag whose default is a `RelativeToRoot`.** The command exited 1 with `payload does not satisfy the declared schema ... the value is not representable in JSON` -- a read-only command refusing its own declaration, while the human form printed the same row fine. The machine form now publishes the marker in the shape `--dump-schema` already uses, `{"relative_to_root": {"env_var": ..., "parts": [...]}}`: the declared environment variable and path parts, never the resolved machine-specific path. The human rendering is unchanged.
